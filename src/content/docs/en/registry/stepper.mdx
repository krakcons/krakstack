# Stepper

A stepper shows progress through named steps. It is not a slider: sliders choose values by dragging a handle. The live example below uses compact underlined labels, with Previous and Continue transitions.

## Installation

```bash
bunx shadcn@latest add @krak-stack/stepper
```

Import from `@/components/ui/stepper` after a registry installation, or from `@krak-stack/registry/stepper` with a package release containing this export.

## Controlled navigation

```tsx
import { Stepper } from "@/components/ui/stepper";

const steps = [
  { id: "connect", label: "Connect", state: "completed" },
  { id: "configure", label: "Configure" },
  {
    id: "verify",
    label: "Verify",
    disabled: true,
    disabledReason: "Finish configuration first",
  },
] satisfies Parameters<typeof Stepper>[0]["steps"];

<Stepper
  steps={steps}
  currentStep="configure"
  onStepSelect={(step) => requestNavigation(step.id)}
  aria-label="Project setup"
/>;
```

Selection requests navigation; it never changes the current step or submits a form. Update `currentStep` only after the host accepts navigation. Omit `onStepSelect` for read-only tracking. IDs must be unique and stable, and `currentStep` must identify an existing step; an empty list or unknown current ID renders nothing.

Each step accepts `label`, optional `description` and `icon`, explicit `state` (`upcoming`, `completed` or `error`), and optional `disabled`/`disabledReason`. Earlier steps are not assumed complete. Unavailable buttons stay discoverable with `aria-disabled`, but do not invoke selection. Supply a reason when the restriction is not obvious. Callbacks remain synchronous requests; handle async errors in your host rather than throwing unhandled promises from the callback.

## Presentation and layout

Use `variant="underline"` for compact, centered text labels with a thin underline on the active step: no numbers, circles or checkmarks. Labels wrap on narrow screens instead of stretching across the page. Completed steps retain quiet styling and accessible completion text. The live preview uses this presentation.

The existing `variant="labelled"` (default) and `variant="segmented"` remain available. Orientation is `horizontal` (default), `vertical`, or `responsive` (compact numbered steps below the large breakpoint, a labelled vertical rail above it). Segments keep their labels available to assistive technology.

The component does not impose a page shell. Compose it above content, in a sidebar, or in your own grid. Use `className`, theme tokens and the `data-slot`, `data-variant`, `data-orientation`, `data-state` and `aria-current` hooks. It requires no router, form library, context setup or animation dependency.

## Examples

The live examples show three compositions with the same API:

- **Compact navigation:** centered underlined labels with fixed Previous/Continue controls and an optional directional slide.
- **A form with review:** a required field, a review step and explicit confirmation. Forward steps are unavailable until the host advances. The example owns its draft in React state and uses native required-field validation; Previous is `type="button"` and never submits. No server save is simulated.
- **Read-only progress:** vertical text labels, descriptions and explicit completed/error states, without interactive triggers or numbered indicators.

For a vertical read-only layout, omit the selection callback:

```tsx
<Stepper
  variant="underline"
  orientation="vertical"
  currentStep="configure"
  steps={[
    {
      id: "connect",
      label: t.connect,
      description: t.connected,
      state: "completed",
    },
    {
      id: "configure",
      label: t.configure,
      description: t.attention,
      state: "error",
    },
    { id: "verify", label: t.verify, description: t.waiting },
  ]}
/>
```

Here `t` represents your application's localized labels. Prefer composition with your existing form and buttons over a workflow-specific stepper API. For a side-by-side layout, place this navigation and your content in a responsive CSS grid; the stepper does not own the page shell.

These examples take inspiration from [ReUI's composable stepper](https://reui.io/docs/components/base/stepper) and [Shadcn Studio's layout examples](https://shadcnstudio.com/docs/components/stepper?base=base), while keeping KrakStack's controlled API and compact text presentation.

## Forms and routes

- Previous and earlier-step navigation should not validate or save the current form.
- Continue is a host-owned submit button: validate, save, then change the current step or navigate.
- Keep saving feedback visible until navigation commits. On failure, retain the fields and show an actionable inline error; do not advance.
- Preserve unsaved drafts in your own state when users may return to a step. The stepper does not persist fields, authorize access or decide which steps can be visited.
- For routes, have `onStepSelect` request router navigation, and derive `currentStep` from the committed route. Keep the content wrapper mounted in the common route layout.

## Optional content transitions

```tsx
import { StepperContent } from "@/components/ui/stepper";

<StepperContent
  step={currentStep}
  direction={direction}
  animate
  focusTarget="h2"
>
  <h2 tabIndex={-1}>{title}</h2>
  {content}
</StepperContent>;
```

The host supplies `direction="forward"`, `"backward"` or `"none"` based on its navigation intent. `animate` is off by default. Moving forward slides the previous panel out to the left while the next panel enters from the right; moving backward reverses both directions. Both run together over 500ms with balanced easing and no fade. The outgoing panel is an inert, accessibility-hidden DOM copy captured before the update, not a second live React form. Its IDs and field names are removed and its form controls disabled; it is discarded when the animation finishes or navigation interrupts it. Canvas and other non-DOM rendering are not captured. The outer viewport stays stationary and clips horizontal overflow. Put borders and surface styling on a child inside `StepperContent` to slide both outlines with their content. `none` skips the transition. Initial rendering is not animated, and reduced motion is respected. Unsupported browsers change content immediately.

The preview keeps Previous and Continue outside the sliding panel. Previous appears immediately when available, without a fade. A placeholder reserves its space when absent, so Continue stays in place. This action composition remains host-owned.

Do not key or remount `StepperContent` per step. Key the form inside it if the form needs resetting. `focusTarget` is opt-in and focuses a matching descendant only on step changes, without scrolling. Omit it when your router already manages focus. The wrapper neither hides inactive panels nor stores drafts; render the desired content yourself.

## Accessibility and localization

Progress uses an ordered list inside a labelled navigation region, one `aria-current="step"`, a polite step-count announcement, and native buttons activated with Enter or Space. This is navigation, not a tablist, so Tab visits the controls normally. Completion and error states have text equivalents. Give each content section a heading and arrange focus appropriately after navigation.

EN/FR defaults follow `KrakstackProvider`. Pass `locale` for an override or `messages={{ es: { label: "Progreso", progress: (current, total) => `Paso ${current} de ${total}`, completed: "Completado", error: "Revisar" } }}` for another language. Exact locale overrides take precedence over base-language overrides, then built-in defaults. Step labels and descriptions are always host-owned localized text.
