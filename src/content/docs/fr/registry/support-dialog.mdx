# Formulaire de soutien

Affichez `SupportForm` directement sur une page de soutien. Les utilisateurs peuvent sélectionner ou coller jusqu’à trois captures d’écran PNG, JPEG ou WebP de 5 Mio chacune. Votre application choisit le mode d’envoi.

```bash
bunx shadcn@latest add @krak-stack/support-dialog
```

```tsx
import { SupportForm } from "@/components/support";

<SupportForm
  defaultReplyEmail={user?.email}
  supportEmail="support@krakconsultants.com"
  onSubmit={sendSupportRequest}
/>;
```

Le composant est aussi exporté par `@krak-stack/registry/support`. L’adresse de réponse est facultative : on peut la saisir, la modifier ou l’effacer. Utilisez `askForReplyEmail` pour la rendre obligatoire ou `askForReplyEmail={false}` pour masquer le champ. `supportEmail` ajoute un lien courriel sous le formulaire sans définir la destination des demandes.

Les textes sont fournis en français et en anglais. Le formulaire suit la langue de `KrakstackProvider`, sauf si vous précisez `locale`. Pour personnaliser certains textes, utilisez par exemple `messages={{ fr: { title: "Contacter le soutien" } }}`.

## Commentaires sur une page d’erreur

Utilisez `SupportDialog` avec la propriété `renderFeedback` d’`ErrorComponent`. La case à cocher joint les mêmes détails que la page propose de copier. L’utilisateur peut la décocher pour ne pas les joindre.

```tsx
<ErrorComponent
  {...errorProps}
  renderFeedback={(errorDetails) => (
    <SupportDialog
      trigger={<Button variant="outline">Commentaires</Button>}
      errorDetails={errorDetails}
      supportEmail="support@krakconsultants.com"
      onSubmit={sendSupportRequest}
    />
  )}
/>;
```

## Traiter l’envoi

`onSubmit` reçoit `{ message, attachments, replyEmail?, errorDetails? }`, où `attachments` est une liste d’objets `File`. Résolvez la promesse lorsque la demande est acceptée ou signalez une erreur pour conserver le brouillon. Ne traitez pas l’adresse de réponse comme une preuve d’identité.

Utilisez des données multipart pour envoyer les fichiers. Appliquez des limites côté serveur, validez les données avec `SupportRequestSchema` et vérifiez le contenu réel des images. Gardez les identifiants d’accès et le choix du destinataire côté serveur. N’incluez pas les demandes dans la télémétrie et ne transmettez que des diagnostics qui peuvent être communiqués.
